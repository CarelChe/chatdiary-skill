# 记忆系统审查流程

当用户说"阅读我的日记，审查记忆系统"或类似请求时，执行以下流程：

## 标准流程

### 第一步：列出所有条目
将 MEMORY.md 和 USER.md 的内容分别列出，每条加序号。格式：

```
MEMORY.md（共XX行）

1. 第一条内容...
2. 第二条内容...
...

USER.md（共XX行）

1. 第一条内容...
2. 第二条内容...
...
```

### 第二步：用户决策
用户会告诉你要：
- 删除：哪些序号
- 更新：哪些序号，内容是什么
- 合并：哪些重复条目

### 第三步：执行更新
按用户指令逐条执行 patch，用 `§` 作为行分隔符。

## 常见重复项（供参考）

| 内容 | 常见位置 | 处理方式 |
|------|----------|----------|
| 日记AI风格 | MEMORY + USER | 保留USER |
| 日记记录要求 | MEMORY + USER | 保留USER |
| 基本信息（姓名/生日） | MEMORY + USER | 合并到USER，MEMORY留引用 |
| 副业/求职/学习目标 | 两者都有 | 保留USER更详细版本 |
| 偏好类条目 | 两者都有 | 保留USER |

## 记忆文件路径
- MEMORY.md: `$HERMES_DATA_DIR/memories/MEMORY.md`
- USER.md: `$HERMES_DATA_DIR/memories/USER.md`
- 备用路径（如/docker权限问题）: `$HERMES_APP_DIR/.env` 已复制到 `$HERMES_DATA_DIR/.env`

## 审查原则
- 删：不重要的、过时的一次性事件（旅行/聚会记录等）
- 留：长期有效的状态、偏好、规则
- 合并：重复内容整合到一处，避免维护两份
- 更新：日期/版本/状态等已变化的信息
